If you've recently started learning backend development, you've probably heard about Node.js. You might also have come across terms like Express.js, npm, APIs, callbacks, Promises, and the Event Loop.

Initially, all these terms can sound confusing. But don't worry! In this blog, we'll understand Node.js from scratch using simple language, real-life examples, and practical code snippets.

By the end of this article, you'll understand what Node.js is, why we use it, how it works, and how its important concepts fit together.

1. What is Node.js?

Let's start with a simple question: Can JavaScript run outside a web browser?

When we think about JavaScript, we often think about websites. You open a browser, visit a site, click a button, and JavaScript makes the page interactive. Traditionally, JavaScript was primarily used inside web browsers.

But what if we want to use JavaScript to:

  • Read files from a computer.
  • Connect to a database.
  • Create a web server.
  • Build APIs.
  • Handle user login and registration.

This is where Node.js comes into the picture.

Node.js is a JavaScript runtime environment that allows us to execute JavaScript outside the browser. It provides the environment and tools to run JavaScript on a computer or server without needing a web browser.

JavaScript vs Node.js

JavaScriptNode.js
A programming languageA runtime environment
Defines syntax and logicExecutes JavaScript outside the browser
Used for frontend and backend developmentCommonly used for backend development
Browser APIs provide features like DOM manipulationProvides features like file-system access and server creation

Think of JavaScript as the language you speak and Node.js as the environment where you can use that language outside the browser.

2. Why Do We Need Node.js?

Imagine you're building a website where users can register and log in. When someone enters their email and password, your application needs to:

  1. Receive the email and password.
  2. Check whether the user exists.
  3. Connect to a database.
  4. Verify the password.
  5. Return a response saying whether the login was successful.

This is backend functionality. JavaScript running in the browser is not enough to safely handle all these responsibilities. We need a backend environment, and Node.js allows us to write JavaScript code that handles these operations.

Understanding frontend, backend, and database

Frontend: The part of the application users see and interact with. React, Angular, and Vue are commonly used here.

Backend: Handles business logic, processes requests, performs authentication, and communicates with databases. Node.js can be used here.

Database: Stores information such as users, products, and orders. MySQL and MongoDB are examples.

For example, when a user logs in, React displays the form, Node.js handles the login request, and MySQL stores and retrieves user information. This is how these technologies work together.

3. How Does Node.js Execute JavaScript?

Let's create our first Node.js program. Create a file called app.js and write:

console.log("Hello World");

Open your terminal and execute:

node app.js

Output:

Hello World

We created a JavaScript file, executed it using the Node.js command, and saw the output in the terminal. We didn't need to open a browser. That's the basic working of Node.js.

4. What Is a Server in Node.js?

This is one of the most important concepts in backend development. Let's understand it with a restaurant example:

  • Customer = Client
  • Waiter = Request handler
  • Kitchen = Server
  • Food = Response

The customer orders food. The waiter takes the order to the kitchen. The kitchen prepares the food, and the waiter delivers it to the customer. A web server works similarly:

  1. Your browser sends a request to the server.
  2. The server receives the request.
  3. The server performs the required operation.
  4. It sends a response back to your browser.
  5. Your browser displays the result.

Node.js can be used to create this server. It provides a built-in module called http that allows us to create an HTTP server. Create a file called server.js:

const http = require('http');

const server = http.createServer((req, res) => {
    res.write('Hello! Welcome to my website');
    res.end();
});

server.listen(3000, () => {
    console.log('Server is running on port 3000');
});

Run the server with node server.js. You should see Server is running on port 3000. Now open your browser and visit http://localhost:3000. You should see Hello! Welcome to my website.

Congratulations! You've created your first Node.js server.

res.write()Writes response content

5. What Is npm?

Imagine you're building a house. You need bricks, cement, paint, doors, and windows. Instead of manufacturing everything yourself, you purchase ready-made materials.

Programming works similarly. Developers create reusable pieces of code called packages. Instead of writing everything from scratch, we can install packages and use them in our applications.

npm stands for Node Package Manager. It helps developers install, manage, and maintain packages required by their projects.

For example, to install Express.js, run:

npm install express
  • npm is the package manager.
  • install is the command.
  • express is the package name.

Think of npm as a shopping store for programming packages.

6. What Is Express.js?

Node.js allows us to create servers, but writing everything with Node.js's built-in HTTP module can become lengthy as an application grows. Imagine an application with 50 different API endpoints: managing every incoming request manually would become difficult.

Express.js is a web framework for Node.js that makes building web servers and APIs easier. Think of Node.js as the kitchen and Express.js as the manager who organizes the kitchen and makes order handling easier.

Node.js vs Express.js

Node.jsExpress.js
Runtime environmentWeb framework
Executes JavaScript outside the browserSimplifies server and API development
Provides built-in modules such as HTTP and FSProvides routing and middleware functionality
Can create servers without ExpressRuns on top of Node.js

Creating a server using Express.js

First, initialize your project and install Express:

npm init -y
npm install express

Create a file called server.js:

const express = require('express');

const app = express();

app.get('/', (req, res) => {
    res.send('Hello from Express!');
});

app.listen(3000, () => {
    console.log('Server running on port 3000');
});

Run node server.js and visit http://localhost:3000. The page displays Hello from Express!. Notice how much simpler it is to create a server using Express.

7. What Are APIs in Node.js?

API stands for Application Programming Interface. In simple words, an API allows two applications to communicate with each other.

Imagine you're building a GitHub Profile Analyzer using React. A user enters their GitHub username and clicks Search. Behind the scenes:

  1. React sends a request to the backend.
  2. Node.js receives the request.
  3. Node.js calls the GitHub API.
  4. GitHub returns profile information.
  5. Node.js sends the information back to React.
  6. React displays the profile.

This is how frontend and backend applications communicate.

Creating a simple API using Express

const express = require('express');

const app = express();

app.get('/user', (req, res) => {
    res.json({
        name: 'Tanay',
        age: 25,
        technology: 'React'
    });
});

app.listen(3000, () => {
    console.log('Server running on port 3000');
});

Now visit http://localhost:3000/user. The response is:

{
    "name": "Tanay",
    "age": 25,
    "technology": "React"
}

Here, /user is called an API endpoint. The res.json() method sends a JSON response to the client.

8. What Is Asynchronous Programming?

This is one of the most important concepts in Node.js. Imagine you visit a restaurant and order food. The waiter tells you that it will take 20 minutes. Should you stand in front of the kitchen doing nothing? Of course not! You can sit at your table, talk to your friends, or use your phone. When your food is ready, the waiter brings it to you.

Programming works similarly. Suppose Node.js needs to read a file or fetch data from an API. Instead of blocking the main JavaScript thread while waiting, Node.js can continue processing other work. This is called asynchronous programming.

A. Callback functions

A callback is a function passed as an argument to another function, which can be executed later.

function orderFood(callback) {
    console.log('Food ordered');
    callback();
}

orderFood(function() {
    console.log('Food is ready');
});

Output:

Food ordered
Food is ready

Think of a callback as telling someone, “Call me when the food is ready.” Callbacks are commonly used in asynchronous operations, although not every callback is asynchronous.

B. Promises

A Promise represents the eventual result of an asynchronous operation. Think of a restaurant promising to deliver your food. There are three states:

  1. Pending: Food is being prepared.
  2. Fulfilled: Food is ready.
  3. Rejected: Food could not be prepared.
const foodOrder = new Promise((resolve, reject) => {
    let foodAvailable = true;

    if (foodAvailable) {
        resolve('Food is ready!');
    } else {
        reject('Food is not available');
    }
});

foodOrder
    .then(result => console.log(result))
    .catch(error => console.log(error));

Output: Food is ready!

  • resolve() indicates successful completion.
  • reject() indicates failure.
  • .then() handles successful Promise fulfillment.
  • .catch() handles rejection.

A Promise allows us to manage asynchronous operations in a more organized way.

C. Async and await

JavaScript also provides async and await for writing code that looks simple and executes step by step, without chaining multiple .then() calls.

function orderFood() {
    return new Promise((resolve) => {
        setTimeout(() => {
            resolve('Food is ready!');
        }, 2000);
    });
}

async function eatFood() {
    console.log('Ordering food...');
    const result = await orderFood();
    console.log(result);
}

eatFood();

Output:

Ordering food...
Food is ready!
  • async makes a function return a Promise.
  • await pauses the execution of that async function until the Promise settles.
  • Other work can continue while the Promise is pending.
My recommendation: Understand callbacks first, then Promises, and finally async/await. These concepts are extremely important when working with APIs and databases.

9. What Is the Event Loop in Node.js?

The Event Loop helps Node.js manage asynchronous operations and determine when their callbacks can be executed. Imagine Node.js has a manager who receives multiple tasks: print a message, read a file, call an API, and print another message. Some tasks take more time than others.

Let's understand with an example:

console.log('First');

setTimeout(() => {
    console.log('Second');
}, 2000);

console.log('Third');

Output:

First
Third
Second

Why does this happen?

  1. First is printed immediately.
  2. The timer is scheduled for approximately two seconds.
  3. Third is printed immediately without waiting for the timer.
  4. After the timer expires, its callback becomes eligible to run and Second is printed when the event loop can process it.

Is Node.js single-threaded?

You'll often hear that Node.js is single-threaded. JavaScript execution normally happens on one main thread. However, Node.js can handle asynchronous operations efficiently using the Event Loop, operating-system facilities, and a background thread pool for certain operations.

This means Node.js doesn't need to block its main JavaScript thread while waiting for many I/O operations to finish. That's one reason Node.js is popular for applications that handle many concurrent network requests.

10. What Are Modules in Node.js?

Imagine you're working on a large school project. Instead of writing everything in one notebook, you divide your work into different notebooks: Mathematics, Science, and English. Programming works similarly. We divide code into different files called modules so it becomes easier to organize, reuse, and maintain.

math.js

function add(a, b) {
    return a + b;
}

module.exports = add;

app.js

const add = require('./math');

console.log(add(10, 20));

Output: 30

  • module.exports exports functionality from a file.
  • require() imports functionality into another file.

These are examples of CommonJS modules. Node.js also supports ES Modules using import and export:

export function add(a, b) {
    return a + b;
}

And import it using:

import { add } from './math.js';

Node.js provides several built-in modules that we can use directly without installing additional packages. Think of them as tools already available in your toolbox.

Example: Reading a file using the FS module

Create a file called data.txt and add Hello, I am learning Node.js!. Now create app.js:

const fs = require('fs');

fs.readFile('data.txt', 'utf8', (err, data) => {
    if (err) {
        console.log(err);
        return;
    }

    console.log(data);
});

Output: Hello, I am learning Node.js!

fs.readFile() reads a file asynchronously. Its callback receives err, which contains any error, and data, which contains the file contents when the read succeeds.

12. What Is package.json?

Imagine you're sharing your project with another developer. They need to know the project name, which packages are required, the project version, and which commands can be used to run it. This information is stored in a file called package.json.

{
    "name": "my-node-project",
    "version": "1.0.0",
    "scripts": {
        "start": "node server.js"
    },
    "dependencies": {
        "express": "^5.0.0"
    }
}

Now you can run your application using npm start instead of manually executing node server.js.

What Is package-lock.json?

package-lock.json records the exact dependency versions and dependency tree used during installation. It helps different developers install consistent versions of project dependencies.

  • package.json describes your project and its dependencies.
  • package-lock.json records the exact dependency resolution.

13. How Do All These Technologies Work Together?

Imagine you're building a Student Management Application. You want users to view students, add students, update student details, and delete students. You can use these technologies:

TechnologyResponsibility
ReactDisplays the user interface
Node.jsExecutes backend JavaScript
Express.jsHandles routes and API requests
MySQLStores student information
npmInstalls and manages packages

What happens when a user clicks “View Students”?

  1. React sends a GET request to the backend.
  2. Express receives the request through the appropriate route.
  3. Node.js executes the backend logic.
  4. The backend fetches student records from MySQL.
  5. The backend sends the records as JSON.
  6. React receives the response and displays the students.

This is how a typical full-stack application works.

14. What Should You Learn Next?

If you're a beginner, I recommend following this learning path:

  1. Node.js fundamentals: What Node.js is, installing it, running JavaScript with it, and understanding the runtime environment.
  2. JavaScript concepts: Callbacks, Promises, async/await, arrow functions, and destructuring.
  3. Node.js modules: CommonJS, ES Modules, require and exports, and fs, path, and http.
  4. npm: Installing packages, package.json, package-lock.json, and managing dependencies.
  5. Express.js: Creating a server, routing, middleware, and request and response objects.
  6. REST APIs: GET, POST, PUT, PATCH, DELETE, and HTTP status codes.
  7. Database connectivity: Connecting Node.js with MySQL or MongoDB, CRUD operations, and database queries.
  8. Authentication and authorization: User registration and login, password hashing, JWT authentication, and role-based authorization.

Conclusion

Node.js is a powerful runtime environment that allows developers to use JavaScript outside the browser. It makes backend development possible using JavaScript and provides features for building servers and APIs, handling files, and communicating with databases.

When combined with Express.js, databases, and frontend frameworks like React, Node.js can be used to build complete web applications.

If you're just starting, don't try to memorize every definition. Focus on understanding:

  1. Why Node.js exists.
  2. How a server works.
  3. How requests and responses work.
  4. How asynchronous programming works.
  5. How Node.js and Express.js work together.

Once these concepts become clear, learning the remaining parts of Node.js will become much easier.
